## 2026-06-16 - Prevent Rate Limit Exhaustion via Negative Caching
**Learning:** In Laravel, `Cache::remember()` bypasses caching entirely if the inner closure throws an Exception. If an expected failure state (like a tracking API returning 'Not Found') throws an Exception, the cache is never populated, causing every subsequent request for that bad ID to hit the API rate limits again.
**Action:** For remote APIs where 'Not Found' is an expected, common, and valid response that needs to be cached, avoid `Cache::remember()`. Use explicit `Cache::get()` and `Cache::put()` to wrap and cache the error payload (negative caching), preventing repetitive failures from draining the rate limit.
